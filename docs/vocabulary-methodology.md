# 語彙データセットの方法論

## 目的と範囲

CEFR A2 の学習者が基礎の抜けを補いながら B2 へ進める、実用的な語彙カバレッジを提供する。
単語の難度は語義や用法でも変わり、唯一の有限な「B2全単語リスト」は存在しない。そのため、
本データセットは **B2到達に必要な4,500見出し語**という選定範囲と作成方法を明示し、「完全収録」とは
表現しない。4,500語という規模は、B2 の語彙サイズの目安として広く挙げられる4,000〜5,000語族に合わせた。

## 見出し語の選定

1. **Oxford 3000 / Oxford 5000（CEFRタグ付き）**を選定の主軸とする。A2・B1・B2に
   割り当てられた見出し語を正規化し、同じ綴りに複数レベルがある場合は、学習開始位置として
   最も低い該当レベルを採用した。
2. 既存の手作業データ1,048語と照合し、未収録だった Oxford A2–B2 の1,950語を追加した。
3. 中級で有用な句動詞 `come across` と `break down` を2語追加し、合計を3,000語とした。
4. 3,000語から **4,500語** への増補では、Oxford 5000 の **C1帯**のうち未収録だった1,267語を採った。
   その多くは既収録語の派生形(`absence` ← `absent`、`acceptance` ← `accept` など)で、基語を知って
   いれば受容は難しくない。**アプリ内のレベル表示は B2 とする**。level の値は「B2到達までに扱う範囲」を
   示すもので、Oxford のタグをそのまま転記したものではない。
5. 増補の残り233語は、Oxford 5000 に単独見出しとして載らないが B2 で必要になる項目を選んだ。
   高頻度句動詞145件(`carry out`、`look into`、`take on` など)、定型表現31件(`in terms of`、
   `on behalf of` など)、日本語母語話者がつまずきやすい派生語・日常語57件(`considerate`、
   `punctual`、`workload` など)である。句動詞と定型表現はレベルを個別に判断し、A2・B1 も含む。
6. **CEFR-J Wordlist**は、日本語母語話者向けの段階性を確認する補助資料として参照した。
7. **English Vocabulary Profile**は、単語全体ではなく語義ごとに難度が変わり得るという
   扱い方の参考にした。

外部リストの定義文や教材文はコピーせず、見出し語とレベルの選定根拠として利用する。

## 現在の規模

| CEFR | 見出し語数 | 位置づけ |
| --- | ---: | --- |
| A2 | 695 | 学習開始時の基礎の抜けを補う |
| B1 | 1,079 | 中級の高頻度語と実用表現を厚くする |
| B2 | 2,726 | B2の読解・聴解で必要になる範囲を広げる |
| **合計** | **4,500** | B2までへの連続した学習プール |

A1語は原則として対象外である。ただし、複数語表現の一部やB1/B2で重要になる語義など、
独立した学習価値がある項目は収録し得る。

## 採用・整理ルール

- **見出し語単位**: `runs`、`running` のような規則的な屈折形は別項目にしない。
- **品詞**: 同じ綴りの高頻度な品詞は、原則として1エントリ内でまとめる。
- **句動詞・複数語表現**: `give up`、`carry out`、`look forward to` のように、まとまりで
  覚える価値が高いものは独立項目にする。
- **多義語**: その例文で学ぶ語義を優先して日本語意味を提示する。すべての辞書的語義は網羅しない。
- **除外**: 固有名詞、極端に専門的な語、単なる大文字・綴り・屈折の重複は原則除外する。

## 意味・発音・例文の作成

### 既存1,048語

日本語意味、品詞、IPA、自然な英語例文と和訳に加え、学習上有用な項目にはコロケーション、
語形成、関連語、記憶の手がかりを個別に収録した。

### 増補1,500語

- **見出し語**: 上記の選定手順4・5による。既収録3,000語との重複、および id 衝突
  (`set up` と `set-up`)を機械的に排除している。
- **発音**: CMU Pronouncing Dictionary の米語 ARPABET をIPAへ変換した。英綴りのみの語
  (`favourable` など5語)は米綴りで引き、表示は英綴りのまま残す。
- **語義・例文・コロケーション・覚えるヒント**: すべて本プロジェクト用に作成した。外部の
  定義文・例文は使用していない。例文は6〜22語、見出し語または自然な屈折形を含み、TTSに
  そのまま渡せる形式にしている。「覚えるヒント」は接辞分解・コアイメージ・既知のカタカナ語への
  接続のいずれかを用い、こじつけの語呂合わせは避けた。

### 拡張1,952語

- **日本語意味**: CC0 の EJDict-hand から候補を取得し、例文の和訳と日本語文字列を照合して、
  その文脈に合う語義を選択した。現代的な用法や表記差が必要な語には個別の補正を加えた。
- **発音**: CMU Pronouncing Dictionary の米語 ARPABET をIPAへ変換した。複数語は構成語を
  結合し、取得できない場合は選定資料の発音表記を正規化した。Web音声の既定も `en-US` とする。
- **例文**: 1,180件は本プロジェクト用に英文と和訳を作成した。770件は Tatoeba の校閲済み
  英日対訳（CC BY 2.0 FR）を採用し、アプリの該当カードに文ID、投稿者、ライセンス、原文リンクを
  表示する。句動詞2件も本プロジェクト用に作成した。

外部例文を使うかどうかにかかわらず、例文は学習対象語または自然な屈折形を含み、注記を混ぜず、
単独でTTSへ渡せる英文にする。

## エントリの品質基準

全エントリに次を必須とする。

- 日本語の意味（1つ以上）
- 日本語表記の品詞
- スラッシュで囲んだIPA発音
- 対象語を文脈内で使う英語例文と、その自然な和訳
- CEFRレベル（A2 / B1 / B2）
- 「覚えるヒント」（接辞分解・コアイメージ中心の日本語解説文）
- コロケーション（1件以上。原則2〜3件）
- 外部例文を使用する場合の出典・URL・ライセンス・帰属表示

語形成と関連語は、正確で学習価値がある場合に加える。
語源は独立した項目として持たない（`mnemonic` の中でも、不確かな由来を断定して書かない）。

### コロケーションの後付け

当初コロケーションを持っていたのは手作業データ1,048語だけだった。残る1,953語（`expanded.ts`
中心）には後から追加し、全4,500語がコロケーションを持つ状態にした。既存データは書き換えず、
`notes.ts` と同じ方式で `collocations.ts`（id → 文字列配列）を作り、`index.ts` で合流させる。
自前の `collocations` を持つエントリが優先で、後付け分は不足を埋めるだけである。

## 自動検証

`npm run validate:content` は実際にアプリが読む統合データを対象に、次を検証する。

- 収録数がちょうど4,500語で、内訳が A2 695 / B1 1,079 / B2 2,726であること
- 全語がコロケーションと「覚えるヒント」を持ち、コロケーションの1件以上が見出し語を含むこと
- IDと大文字・小文字を正規化した見出し語が重複しないこと
- 意味、品詞、IPA、例文、和訳、レベルに欠損や仮置き値がないこと
- 例文がTTS向けの禁止注記記号を含まず、見出し語または自然な屈折形を使っていること
- 外部例文の出典名、HTTPS URL、ライセンス、帰属情報が揃っていること

語彙セッションのテストでは、重複なしの初回5語、未知語だけの再出題、未知語が0になるまでの
反復、localStorageの進捗、復習優先度も別途検証する。

## データと生成処理

- 型: `src/content/types.ts` の `VocabularyEntry`
- 既存の詳細データ: `src/content/vocabulary/batch*.ts`
- 拡張データ: `src/content/vocabulary/expanded.ts`
- 増補データ: `src/content/vocabulary/extended.ts`
- 追加句動詞: `src/content/vocabulary/supplemental.ts`
- 統合入口: `src/content/vocabulary/index.ts`
- 差分分析: `scripts/analyze-vocabulary-expansion.mjs`
- 語義・発音・対訳の準備: `scripts/prepare-vocabulary-expansion.mjs`
- 型付きデータ生成: `scripts/generate-vocabulary-expansion.mjs`
- 独自例文ソース: `scripts/vocabulary-expansion-examples.tsv`
- 増補分の作業ツール: `scripts/vocab4500.mjs`(`prepare` / `status` / `check` / `build`)
- 増補分の台帳と本文: `scripts/vocab4500-meta.tsv`、`scripts/vocab4500-extras.tsv`、
  `scripts/vocab4500-content.tsv`
- コロケーション後付け: `scripts/collocations.mjs`(`status` / `build`)と
  `scripts/vocab-collocations.tsv` → `src/content/vocabulary/collocations.ts`

増補分は `npm run vocab4500 check` が取り込み前に例文の語数・禁止記号・見出し語の使用・
解説文の長さを全件まとめて検査する。`npm run vocab4500 build` は未執筆の語が残っていれば失敗する。

コンテンツはUIから分離し、選択・再試行・復習優先度も `src/services/` の純粋関数として管理する。
このため、表示を変更しても語彙データやセッションの規則を独立して検証できる。
