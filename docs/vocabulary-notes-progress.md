# 語彙「覚えるヒント」解説文 — 進行記録

3,000語すべてに、Stock 3000 のような「読めば意味が腑に落ちる」日本語解説文を付ける作業。
**完了(3,000/3,000)。** 以下の手順は語の追加・文面の差し替えのときにそのまま使える。

中断・レートリミットに備え、別セッションからでも同じ手順で再開できる。

> 4,500語への増補分(1,500語)はこの手順の対象外。解説文は `extended.ts` に `mnemonic` として
> 直接持ち、`scripts/vocab4500.mjs` が生成する。文面のスタイルと検証は下記と同じ基準に従う。

## データの置き場所

- 解説文: `src/content/vocabulary/notes.ts`（id → 解説文の 1 マップ。**手で編集しない**）
- 合流: `src/content/vocabulary/index.ts` が `mnemonic` として各語に載せる
- 表示: `src/pages/Vocabulary.tsx` の「覚えるヒント」（`<details open>` で常時展開）

既存データ（`batch*.ts` / `expanded.ts`）は書き換えない。既に `mnemonic` を持つ 22 語は対象外。

## 再開手順

```bash
npm run notes status 100          # 進捗と、未作成の先頭100語を TSV で出力
                                  # 列: id / level / 品詞 / 語義 / 例文
npm run notes add < batch.json    # {"id":"解説文", ...} を追記(既知IDのみ・上書き可)
```

`status` は「解説文がまだ無い語」だけを固定順で返すので、出力の先頭から順に埋めていけばよい。
1回あたり 100 語程度が扱いやすい。

## 解説文のスタイル

- 日本語 40〜110字、1〜2文。語義の言い換えではなく **なぜその意味になるか** を書く。
- 使えるものを優先順に: ①語源・接辞（ラテン語/ギリシャ語の分解）②コアイメージ ③既知のカタカナ語や
  身近な派生語への接続 ④典型的に使う場面。どれも無理なら語形・音の連想。
- こじつけの語呂合わせは避ける。語源が不確かな場合は「〜のイメージ」と書き、断定しない。
- 例文・コロケーションと矛盾しないこと。多義語は中心義から周辺義への広がりを 1 文で結ぶ。

## 検証

`src/content/content.test.ts` の「全語に覚えるヒント(mnemonic)がある」が、
4,500語すべてが解説文を持つことを検証する。増補分は `npm run vocab4500 check` が20字以上を要求する。`npm test` / `npm run lint` / `npm run build` で確認。
